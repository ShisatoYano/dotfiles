# 自己レビューチェックリスト

`bug-investigation-workflow`/`implementation-workflow`の「実装・自己レビュー」から参照される、diffレビュー時の観点。

- 意図しない変更(デバッグ用の記述の残存、無関係な差分など)が混入していないか
- 過剰な抽象化・不要なエラーハンドリングが混入していないか
- コメントが「その場で知らないと誤って直してしまう情報」(Why not・外部制約)に限られ、1〜2行に収まっているか。How/Whatや経緯を書いていないか
- 既存環境が依存している識別子(ファイルパス・ファイル名・設定キー)を、必要もなく変えていないか。変える場合、旧識別子が残って衝突しないか
