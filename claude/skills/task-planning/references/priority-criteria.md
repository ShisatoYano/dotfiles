# タスク優先度判定基準

`task-planning`の「手順」から参照される、並び替えの観点(機械的な絶対順位ではなく判断材料として扱う)。NotionとGitHubのタスクは、下の読み替えで同じ基準に載せて1つの順に並べる。

- `ステータス`が`Doing`(着手済み)のタスクは基本的に他より優先するが、絶対ではない
- 次点は以下の2グループを**同格**として扱う(どちらかを機械的に優先しない): (a) `期限`があるタスクを期限昇順・優先度順に並べたもの、(b) `期限`が未設定でも`種類`が`Issue (Fix)`かつ`優先度`が`Highest`のタスク
- 上記以外(期限なし・Issueでもない)は優先度順で最後に並べる

## GitHubのIssueの読み替え

- `Doing`: 自分の未完了のPRの`closingIssuesReferences`に含まれるIssue、`daily-task-logs`の持ち越しにあるIssue、または計画(`plan`)から選んだ1件でProjectの`Status`が`In Progress`のもの
- 計画から選んだ1件で`Doing`に当たらないものは、計画で次にやると決めたものなので、期限なしのタスクの先頭に置く
- `期限`: マイルストーンの期日(`dueOn`)。無ければ期限なし
- `Issue (Fix)`かつ`Highest`: `bug`ラベルと、優先度の高さを示すラベル(`priority: high`、`critical`など)の両方があるもの
- 優先度: 優先度のラベルがあればそれ、無ければ同じ段の中では番号の小さい(古い)順
