# レビュー観点・出力基準

`pr-workflow`の「レビュー実施」で、メインセッション(深さ判定)とレビュー用サブエージェント(観点・出力)の両方から参照される。

## 深さの判定

既存ファイルへの変更(`modified`の行数とパス)を主に見て決める。新規ファイルだけのコードにはdiff外の呼び出し元が無いので、行数が多くても重点にしない。迷ったら1段深い方にする。

| 深さ | 条件の目安 | 読む範囲 | サブエージェントのモデル |
|---|---|---|---|
| 軽量 | 新規コードが無く、docs・コメント・設定値のみ、または既存ファイルの変更50行以下 | diffのみ | `sonnet` |
| 標準 | 上下どちらにも該当しない(新規パッケージの追加を含む) | diff+変更箇所の周辺コード(同一リポジトリ内) | 既定 |
| 重点 | 既存の公開インターフェース・共有ライブラリ・並行処理・安全/セキュリティ・データ移行に触れる、または既存ファイルの変更500行超 | 標準+diff外の呼び出し元・利用箇所(他リポジトリを含む) | 既定 |

- 他リポジトリのコードを読んで前提を確かめるのは重点のみ。標準で他リポジトリ次第になるものは質問にするか、未確認に書く
- 新規コードが1500行を超える場合は、中核のロジックを優先して読み、読み飛ばしたファイルを未確認に書く

## 読まなくてよいもの

lockファイル・自動生成コード・vendorされた外部コード・スナップショット/フィクスチャ等の大きなデータは、変更されたことだけ確認し、中身は読まない。

## 必須観点

深さに関わらず全て確認する。

- 意図との一致: PR本文・リンクされたissueが述べる目的をdiffが実現しているか。やり残し・目的外の変更が混ざっていないか
- 正しさ: 境界値・エラー経路・null/空・単位/座標系・並行アクセスで壊れないか
- 影響範囲: 変更したシグネチャ・挙動・設定キーの利用箇所がdiff外に残っていないか(重点のみ必須、標準では疑わしい場合のみ)
- テスト: 変更された挙動に対応するテストがあるか。無い場合、どのケースが欠けているか
- 安全側の担保: エラーハンドリング・入力検証・権限・後方互換が落ちていないか

## 出力ルール

修正すべきか曖昧な指摘はレビュイーを困惑させるため、投稿用には「Must」と「質問」の2区分だけを出す。

- Must: 通常の使い方で起きる誤動作・データ破損・仕様違反、または悪用できるセキュリティ問題(攻撃は「通常の使い方」の外なので、別に明記している)。「〜してはいかがでしょうか」ではなく、直す必要があると言い切れるものに限る
- 質問: 前提(対象環境・バージョン・実行ユーザー・運用構成など)次第でMustになるもの。前提がPR本文・README・コード(`path:line`)のいずれかで確認できるものは、質問にせずMustか対象外に確定させる。確定できないものだけを質問にする
- 上記に当たらないもの(保守性・命名・書式・テスト追加の提案・好み)は出力しない。linter/formatter/CIが検出するものも書かない
- 各Mustには、理由(どの入力・状態で何が起きるか)と修正案(具体的な変更、設計に関わる場合は方針)を付ける。どちらも書けないものはMustにしない
- 文の数は厳守する: Mustの問題1文・理由は矢印でつないだ1文・修正案2文以内、質問は全体で2文以内(括弧の補足は使わない)。別の攻撃経路・関連する懸念などの追記はしない
- Mustと質問は合計5件まで(超えたら重大な順に残し、残りは件数だけ書く)
- 既存のレビューコメント・未解決スレッドで指摘済みの内容は繰り返さない
- 投稿用の文面は、そのままPRのインラインコメントに貼れる敬体にする
- 確認できなかった範囲(ローカルクローンが無く呼び出し元を見ていない、添付画像、巨大ファイルを読み飛ばした等)は「レビュアー向けメモ」の未確認に書く

## 出力形式

```
### <owner/repo>#<number> <title>  [深さ: 軽量|標準|重点]
概要: 何を変えるPRか、意図とdiffが一致しているか(1〜2行)

【投稿用】
Must:
- <path>:<line> — <問題(1文)>
  理由: <入力・状態> → <起きること>
  修正案: <具体的な変更 or 方針(2文以内)>
質問:
- <path>:<line> — <確認したい前提と、答え次第でMustになる理由(2文以内)>
(Must・質問とも無ければ「指摘なし」)

【レビュアー向けメモ】(投稿しない)
未確認: <無ければ「なし」>
推奨: approve可 / 要修正 / 要相談(理由1行)
```
