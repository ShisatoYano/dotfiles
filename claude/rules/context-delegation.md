# コンテキスト委譲時のモデル選定

読み取り専用でルールベースな情報収集ステップは、Agentツールで別スレッド(ゼロコンテキストのsubagent)に委譲し、`model`をhaikuに落とすことでメインスレッドのコンテキストを節約する。

- **MUST**: 委譲対象は読み取り専用(書き込み・状態変更を伴わない)ステップに限る。書き込みを伴う工程は承認ゲート(`~/dotfiles/claude/rules/write-approval.md`参照)が必要なため委譲しない
- **MUST**: haikuまで落とせるのは、Skillの手順に明文化されたルールを機械的に適用するだけで結論が出るステップに限る。コードやログを読んで因果関係を推論するなど判断の余地があるステップは、委譲はしてもモデルは呼び出し元と同じものを維持する
- 委譲先はゼロコンテキストで起動するため、対象のタスクID・PR番号・実行させるSkill名など、判断に必要な情報をAgentツールのプロンプトに明示する
- **MUST**: 委譲プロンプトは対象Skillの手順を要約・言い換えしない。「`<skill-name>` SkillをSkillツールで呼び出し、その手順に厳密に従うこと」と指示し、Skill本文をfresh agent自身に読ませる。要約すると、地味だが必須な手順(例: 過去ログの確認)が委譲する側の裁量で脱落しうる

## 適用例

- `daily-task-planning`から呼ばれる`pr-task-planning`(PR状態を`reviewDecision`等の明示的な状態で分類)、`notion-task-planning`(期限/優先度による並び替え)は、いずれもSkill手順に書かれたルールの機械適用のみで完結するため、haikuへ委譲する
