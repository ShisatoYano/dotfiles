# 書き込み系アクション承認ゲート

外部に影響する書き込み系アクション(実装方針の確定、Notionページへの書き込み、push・PR作成)は、内容を先にユーザーへ提示し、明示的な承認を得てから実行する。

- **MUST**: 実行前に対象内容(実装方針・影響範囲・テスト方針、Notion追記内容、PR下書きなど)をそのまま提示する。要約や省略をしない
- **MUST**: ユーザーの明示的な承認を得るまで実行しない。コンテキスト圧縮直前の自動サマリ等、急ぐ状況でもこの手順を省略しない
- **MUST NOT**: 承認された範囲を超える変更が必要になった場合、無断で拡大せず、その旨を報告して方針の見直しを確認する

## hookとの役割分担

- `git push`・`gh pr merge/review/comment`・`git checkout`はPreToolUse hookで機械的にブロックされる(`claude/hooks/block-git-push.py`など)。これは「承認前にコマンド自体が実行されない」という最終防波堤
- 実装方針の承認やNotion書き込みの承認は、「実際にユーザーに提示したか」をhookでは検証できない性質のため、hook化せずSkillの手順として守る
